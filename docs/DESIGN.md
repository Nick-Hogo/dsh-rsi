# dsh-RSI 设计思想

> 状态：Phase 1.5（项目工作台）
> 更新：2026-11-10

## 1. 定位与命名

dsh-RSI 是 DSH 侧栏里的 **进化规划器**。它不是又一个聊天入口，也不是自进化引擎本身。

整套架构由三个对象组成：

```
Evolution Planner → Evolution Specification → RSI Engine
进化规划器          → 进化任务规范              → 自进化引擎
```

| 名称 | 职责 |
|---|---|
| 进化规划器（Evolution Planner） | 定义优化什么、允许修改什么、如何判断成功、执行约束是什么 |
| 进化任务规范（Evolution Specification） | 规划器产出的、可确认、可冻结、可交给引擎执行的规范 |
| 自进化引擎（Self-Improvement Engine / RSI Engine） | 生成、评估、选择、改写、递归迭代 |

规划器负责 **定义问题**；引擎负责 **执行优化**。两者之间只有一份显式规范，避免把「目标」「约束」「执行策略」混在提示词或聊天记录里。

规划器之上还有一层**项目台账**：每个 RSI 项目绑定一个目标工作区（引擎只在该工作区内修改），承载一份 `EvolutionSpec` 及其生命周期。侧栏只有一个入口「递归自进化」：数据面板汇总全部项目，详情管理单个项目。

## 2. 第一性问题

任何一次进化任务，在开始生成候选之前，都必须回答四个问题：

1. **优化什么？** —— 期望达到的最终状态，而不是实现步骤。
2. **允许改什么？** —— 目录、文件、模块的修改空间；未列出即不允许。
3. **如何判断成功？** —— 可度量、可复现的评估标准。
4. **在什么约束下执行？** —— 时间、预算、安全边界、最大轮次。

规划器的界面就是这四个问题的结构化容器。没有这四类信息，确认按钮不应生效。

## 3. 设计原则

### 3.1 如无必要勿增实体

- 规划器不复制一份执行状态；它只拥有一份 `EvolutionSpec`。
- 不提前创建引擎目录、空服务或假进度。
- 不为「以后可能用到」而引入 Host 路由、SSE、Remote 命名空间。
- 一个面板解决规划与确认；不拆成向导、弹窗、抽屉三套交互。
- 一个本地存储键；不做多套草稿/历史/草稿箱。

### 3.2 先规划，后执行

确认是一个真实的门槛，不是装饰：

- 必填字段完整、轮次合法、用户勾选确认，三者同时满足才可冻结规范。
- 冻结后字段只读；要改必须显式「返回修改」。
- 本阶段冻结不会启动执行；吸底栏明确写「规范已冻结，等待引擎接入」。

### 3.3 不伪造状态

- 没有引擎就显示「未接入」，不播放假的迭代动画。
- 轮次来自状态对象，不由 UI 猜测或按时间递增。
- 步骤状态只有 `pending / active / done / failed`，没有「大概完成了」。

### 3.4 一个面板，一屏完成

目标、边界、评估、约束、确认、状态在同一个页面内完成。用户不需要在多个弹窗之间跳转，也不需要记住上一步填了什么。

### 3.5 渐进式披露，先跑起来

第一次使用时，用户不应该面对四张空表单。默认只给**一个想法输入框**：

1. 用户输入一句大致想法；
2. 规划器在本地把想法解析成一段可校对的「我的理解」；用户确认意图后，再自动生成四段初稿（目标、修改空间、评估标准、约束）；
3. 四个段落默认折叠为摘要，用户可以直接确认，也可以展开任意一段调整。

这条路径把「开始使用」的成本压到一次输入，并在生成四段表单之前增加一次低成本的「理解校对」。折叠不是禁用，而是按需展开。Phase 1 的意图解析与四段初稿都是本地确定性生成，不调用模型；它们的作用是给出可改写的起点，而不是替代用户的判断。

## 4. 交互模型

### 4.1 状态机

```
idea ──解析意图──▶ intent ──确认意图──▶ draft（review）──确认规范──▶ confirmed ──(引擎接入后)──▶ running ──▶ completed / failed
  ▲                    │                      ▲                              │
  └──返回查看想法───────┘                      └──────────返回修改────────────┘
```

Phase 1 实现 `idea`、`intent`、`draft`（review）与 `confirmed` 四态，但只在步骤条上呈现三个内容页：**想法 / 意图 / 规范**。「确认」是规范页的底栏动作，不占一个步骤。

- `idea`：只显示一个「你的想法」输入框和「解析意图」按钮。
- `intent`：展示可编辑的「我的理解」和解析线索；确认意图后才生成四段规范。规范生成后默认只读，点「修改意图」才解锁。
- `draft`（review）：四段规范已生成，默认折叠为摘要；**一次只展开一段**，底部固定确认栏。
- `confirmed`：字段冻结；底部栏显示「规范已冻结」与「返回修改」。
- `running / completed / failed`：为 Phase 2+ 预留，Phase 1 不出现。

步骤条点击规则：

- 想法：随时可回。
- 意图：解析出意图后可回；规范生成后默认只读。
- 规范：意图确认后可回；意图未确认时禁用。
- 修改想法会让意图/规范过期；修改意图会重新生成四段规范，并明确提示可能覆盖手动修改。
- 上游过期时，下游步骤禁用，并提示「先重新解析 / 先确认意图」。

### 4.2 页面信息架构

整页采用**单栏**，不再有右侧常驻状态栏；所有状态压缩为顶部一条可展开的状态条。

**初始（idea）**

```
页头：品牌 / 标题 / 副标题 / 返回会话
步骤条：① 想法 ── ② 意图 ── ③ 规范
状态条：● 想法 · 0 / — · 引擎未接入        [详情]
主列：
  从一个想法开始
   一个大的想法输入框
   三个示例 chip（点一下填入，可直接改）
   [解析意图]
页脚：阶段标识 / 持久化说明
```

**意图校对（intent）**

```
页头：品牌 / 标题 / 副标题 / 返回会话
步骤条：① 想法 ✓ ── ② 意图（进行中） ── ③ 规范
状态条：● 意图 · 0 / — · 引擎未接入        [详情]
主列：
  意图校对
   原始想法（只读，可返回修改）
   我的理解 [可编辑 textarea]
   解析线索：认证/登录 · 测试 · 性能
底部固定栏：
  [返回查看想法]              [确认意图，生成规范]
```

意图确认前不会生成四段规范；「我的理解」会成为后续规范的目标。

规范生成后再回到意图页，默认只读：

```
  [返回规范]                         [修改意图]
```

- 规范还在草稿：点「修改意图」解锁，底部栏变成「返回查看想法 / 确认意图，生成规范」；
- 规范已确认：只提供「返回规范」，需先回规范页「返回修改」才能修改意图。

**草案（draft / review）**

```
页头：品牌 / 标题 / 副标题 / 返回会话
步骤条：① 想法 ✓ ── ② 意图 ✓ ── ③ 规范（进行中）
状态条：● 草稿 · 0 / N · 引擎未接入        [详情]
主列：
  进化任务规范
   原始想法（两行摘要）+ [查看想法]
   01 优化目标        [摘要]  +
   02 修改空间        [摘要]  +
   03 评估标准        [摘要]  +
   04 执行约束        [最大轮次 + 摘要]  +
底部固定栏：
  ☐ 我已确认…         [提示文字]  [确认进化任务规范]
```

点击任意一行展开该段；展开另一行会自动收起上一行。没有「展开全部」，避免一次看到四张大表单。

**查看想法（点击步骤①或「查看想法」）**

```
步骤条：① 想法（进行中） ── ② 意图 ── ③ 规范
状态条：● 想法 · 0 / — · 引擎未接入        [详情]
主列：
  从一个想法开始
  [可编辑的想法 textarea]
  [返回规范 / 返回意图校对]  [恢复上次解析的想法]  [重新解析意图]
```

- 不修改：点「返回规范 / 返回意图校对」直接回到原步骤。
- 修改了：下游步骤禁用，返回按钮消失；必须重新解析意图，或恢复上次解析的想法。

**已确认（confirmed）**

```
页头：品牌 / 标题 / 副标题 / 返回会话
步骤条：① 想法 ✓ ── ② 意图 ✓ ── ③ 规范 ✓
状态条：● 已确认 · 0 / N · 引擎未接入        [详情]
主列：
  进化任务规范（折叠摘要，可展开查看但不可编辑）
底部固定栏：
  ✓ 进化任务规范已冻结                         [返回修改]
```

窄屏时步骤条、状态条与主列自然堆叠；底部栏变为两行，按钮占满宽度；折叠行隐藏摘要，只保留标题。

### 4.3 两级确认的语义

本阶段有两个不同的确认点，不能合并：

1. **确认意图**：校对「我理解得对不对」。确认后才允许拆成四段规范；此时还没有产生执行许可。
2. **确认规范**：勾选框明确表达「允许引擎在修改空间内迭代」。确认后规范冻结，但仍不会自动启动执行。

具体规则：

- 自动解析可以**直接确认**：适合边界清晰的小任务；用户不需要为了确认而逐个展开。
- 规范确认后展示「进化任务规范已冻结」以及下一步的真实状态：等待引擎。
- 不允许「确认即自动开始」；启动动作属于引擎阶段，需要单独的控制与安全审查。
- 自动解析是本地确定性结果，不伪装成智能规划；需要复杂推理时，用户应修改「我的理解」或展开规范调整，或在 Phase 2 由引擎/LLM 生成更细的内容。

### 4.4 文案与语气

- 技术、克制、可验证；不使用「魔法」「自动变强」一类承诺。
- 区分 **目标**（最终状态）与 **步骤**（实现路径）。
- 评估标准优先鼓励可度量描述。
- 所有面向用户的文案走 `ctx.locale`；中文/英文键集合保持一致。

### 4.5 视觉

- 只使用宿主主题 token（`--dsw-alias-*`），亮暗主题自动跟随。
- 米白/深色卡片 + 细分隔线 + 编号字段，接近工程控制台而不是营销页。
- 状态色只表达状态：进行中、完成、失败、等待。
- 动效仅用于按钮/输入焦点过渡；`prefers-reduced-motion` 下关闭。

### 4.6 数据面板与项目详情

侧栏只有一个入口，打开后是数据面板；项目详情是面板的下一级，返回永远回面板。两级页面遵循同一条约束：**每个信息只表达一次，每个阶段只有一个前进动作，所有前进动作都在吸底栏**。

**数据面板。** 「递归自进化」的首页是全部项目的数据面板，按「总览 → 趋势 → 明细」自上而下分三层，回答三个问题：现在有什么在跑、花了多少资源、哪些需要我处理。

- **关键指标**（第一层，4 列）：运行中（附项目总数）、活跃 Agent（附已分配数）、Token 消耗（附输入 / 输出）、需关注（附失败 / 暂停数）。指标只读，不兼作筛选，避免一个控件承担两种语义。引擎没有上报的指标显示「—」和「引擎接入后统计」，不用 0 冒充真实数据。
- **图表**（第二层，3 : 2 两栏）：左侧「运行进度」是横向条形图，列出运行中、暂停、失败的项目，按紧急程度排序，最多 6 行，每行显示名称、轮次进度条与「轮次 · 阶段」，点击进入项目；右侧「Token 消耗分布」是环形图，按项目统计，前 4 名加「其他」，中心显示总量，图例给出数值与占比，SVG 带文字替代。窄屏时两栏上下堆叠。
- **全部项目**（第三层）：标题右侧是状态筛选标签（全部 / 运行中 / 需关注 / 待启动 / 规划中 / 已完成，带计数，计数为 0 的标签禁用）；项目达到 6 个时出现搜索，2 个以上工作区时出现工作区筛选。任务卡片按紧急程度排序；有运行快照时显示进度条、阶段、Token 与 Agent 用量，失败或暂停时显示原因。
- **演示数据**：引擎接入前所有运行指标都为空，无法评审布局。空状态提供「查看演示数据」，面板切换为一组覆盖全部状态的示例项目，并始终显示演示横幅；演示数据不保存、不能打开或删除，「退出演示」即恢复真实数据。
- 删除是悬停出现的轻量动作，可撤销；运行中或暂停的项目不能删除。空面板只显示一句说明、唯一的「新建项目」按钮和演示入口。

**详情。** 页头依次是「返回面板」、可编辑项目名与状态徽标、单行工作区属性。下面是一个平铺的三段列表 `1 想法 / 2 意图 / 3 规范`：段与段之间只用分隔线，不再套卡片；当前段展开正文，其余段显示一行摘要，被锁定的段直接在摘要位置写出原因（如「先确认意图」），不依赖 tooltip。只有规范段内部保留四段折叠，这是页面里唯一的带框容器。阶段标题是唯一的阶段导航，不再提供「查看想法」「返回规范」等重复出口。

**吸底栏。** 每个阶段的主操作固定在吸底栏：想法段为「解析意图 / 重新解析意图 / 继续」，意图段为「确认意图」或「继续」（锁定时附「修改意图」），规范段为勾选确认与「确认规范」，冻结后为「返回修改」。说明文字只保留一句，放在吸底栏左侧，与动作同时出现。

**工作区。** 工作区是项目属性，不属于想法、意图、规范中的任何一步，因此放在页头而不是想法表单里。有宿主工作区列表时，它是一个看起来像文本的原生下拉框，最后一项「其他目录…」切换为行内路径输入；没有列表时显示当前值与「选择 / 更改」。路径必须是绝对路径；宿主创建失败会显式报错，不再静默降级。默认值为上次使用的工作区。规范确认后工作区、项目名与想法一同只读，需先「返回修改」。

**保存与恢复。** 项目在出现第一段想法时自动保存，离开详情不会丢失输入；被清空的新项目在返回面板时移除。示例只在想法为空时出现，不会覆盖已输入内容。存储不可用时，面板和详情都会显示同一条提示。

## 5. 数据与事实来源

### 5.1 Phase 1

- 唯一数据是**项目台账** `ProjectStore v2`，保存在浏览器 `localStorage` 的 `dsh-RSI.projects.v2`。
- 台账包含 `projects[]` 与 `lastUsedWorkspaceId`；每个项目包含 `id / name / workspace / spec / createdAt / updatedAt`。
- 每个项目只保存一份 `EvolutionSpec v1`，因此刷新后能回到想法、意图校对或规范状态。
- 旧版单规范 key `dsh-RSI.evolution-spec.v1` 在首次加载且 v2 不存在时迁移成一个项目；旧 key 保留不删，便于回滚。
- 没有内容的项目（无想法且无意图）不进入台账；项目出现第一段想法时自动写入，离开详情不会丢失输入。
- 意图解析是确定性函数的结果，不保存模型交互、不保存隐藏推理；只保存「我的理解」文本与解析来源。
- 刷新页面回到数据面板；打开中的项目不单独持久化。
- 浏览器存储不可用时，内存状态继续工作并给出非阻塞提示。

### 5.2 Phase 2+

- 规范由 Host 持久化，成为引擎的唯一输入。
- 引擎上报 `EngineSnapshot`，面板只读展示；UI 不自行推断轮次或步骤。
- 具体存储位置与传输方式在架构文档中定义。

## 6. 明确不做的事

- 不做手工勾选任务状态；规范不是任务列表。
- 不做聊天式规划向导；结构化四问就是规划器。
- 不把 Agent 的 `todo_write` 当作 RSI 计划；两者语义不同。
- 不在 Phase 1 启动引擎、执行评估或修改工作区。
- 不为未来功能预建空目录和空接口。

## 7. 后续交互扩展

引擎接入后，本面板需要在同一信息架构内增加：

- 运行控制：开始、暂停、停止（需要权限与二次确认）。
- 真实轮次：当前轮 / 最大轮，历史轮次列表。
- 步骤详情：每轮生成/评估/选择/改写的结果与耗时。
- 评估结果：指标、通过/失败原因、是否接受改动。
- 失败恢复：失败阶段、日志、重试/回滚。
- 规范版本：已确认规范的版本与变更记录。

这些扩展不应改变「规划器定义问题、引擎执行优化」的边界。

## 8. 设计决策记录

| 决策 | 原因 |
|---|---|
| 面板不绑定聊天会话 | 进化任务属于工作区/项目，不属于某一次对话 |
| 默认只有一个想法输入框 | 把开始使用成本压到最低；四段表单是「需要时」而不是「先填完」 |
| 本地确定性意图解析 | Phase 1 无引擎时也能给出可校对的起点；不伪造 LLM 能力 |
| 三步可点击导航 | 想法 → 意图 → 规范；确认是规范页的底栏动作，不占一步 |
| 意图锁定 | 规范生成后意图默认只读，点「修改意图」才解锁，避免误改导致下游无声变化 |
| 意图先确认，再拆规范 | 先对齐「理解得对不对」，再讨论「怎么改」；避免在错误理解上填四段 |
| 「查看想法」保留原想法 | 返回不丢草稿；修改后要求重新解析，避免下游状态与想法脱节 |
| 一次只展开一段 | 避免四张大表单同时出现，同时保留逐项调整能力 |
| 顶部状态条 + 底部固定确认栏 | 状态可查但不抢焦点；主操作始终可见 |
| 确认后冻结、可返回修改 | 让「确认」有实际约束力，同时保留修正路径 |
| 状态骨架固定六阶段 | 与引擎概念模型一致，未来只需替换数据源 |
| Phase 1 用 localStorage | 最小可用持久化；避免提前引入 Host 服务 |
| 单文件客户端 bundle | 无构建依赖、安装简单；引擎阶段再按需拆分 |
| 侧栏只有一个入口，数据面板与详情在同一面板内切换 | 功能扩张不增加导航噪音，返回语义始终是「回面板」 |
| 项目 1:1 绑定工作区，解析意图前必选 | 引擎的修改空间与回滚点都落在工作区上，没有工作区就不该开始规划 |
| 台账用单 key 存项目数组 | 仍满足「一个本地存储键」，避免多套草稿/历史/草稿箱 |
| 有内容即保存 | 面板不出现空项目，同时离开详情不丢失已输入的想法 |
| 详情三段平铺列表 | 想法/意图/规范在同一屏内逐级展开；只有规范四段保留折叠框，避免框套框 |
| 工作区在页头 | 工作区是项目属性而非规划步骤；单行展示，选择与新建按需展开 |
| 删除可撤销 | 用撤销替代二次确认，删除只需一步且不丢数据 |
| 首页是数据面板 | 侧栏入口的首要任务是看清全局：在跑什么、什么要处理；规划只是其中一种卡片状态 |
| 指标只读、筛选独立 | 指标回答「有多少」，筛选回答「看哪些」；分开后两者的行为都可预测 |
| 三层布局 | 总览 → 趋势 → 明细，先看全局再下钻，符合仪表盘的阅读顺序 |
| 图表用原生 SVG/CSS | 只需条形图与环形图两种，无需引入图表依赖 |
| 演示数据显式标注 | 允许在引擎接入前评审布局，同时不让示例数据与真实数据混淆 |
| 运行数据只来自快照 | 没有 `run` 快照就不显示进度；运行中的规范不能返回修改 |
