# dsh-RSI

DSH 侧栏里的 **递归自进化（Recursive Self-Evolution）** 工作台。

侧栏只有一个入口。打开后先是汇总全部项目的**数据面板**，每个项目在创建时绑定一个目标工作区；点进项目，是 **想法 → 意图 → 规范** 三级可展开的规划器。规范确认后冻结，等待自进化引擎接入。

> 当前是 **Phase 1**：只有项目台账、工作区绑定与规划器。自进化引擎（Self-Improvement Engine）尚未接入，确认规范不会启动任何执行。

## 能力

- DSH 侧栏单入口，点击打开全局面板，不依赖聊天会话。
- **数据面板**：关键指标（运行中、活跃 Agent、Token 消耗、需关注）+ 运行进度条形图 + Token 消耗环形图 + 可筛选的任务卡片；引擎接入前可「查看演示数据」预览布局，数据只来自引擎快照，不伪造。
- **工作区绑定**：每个项目 1:1 绑定一个工作区，作为页头的单行属性展示；解析意图前必选，默认复用上次使用的工作区，也可输入绝对路径新建。
- **三级展开**：想法、意图、规范三段在同一详情页内逐级展开，当前段展开、其余段落折叠并显示摘要。
- **从一个想法开始**：初始只有一个输入框与工作区选择。
- **意图校对**：点击「解析意图」后，先展示一段可修改的意图理解；确认意图后才拆成四段规范。
- **一次只展开一段规范**：目标、修改空间、评估标准、执行约束折叠为摘要，确认是规范页的底栏动作。
- **阶段即导航**：点击想法、意图、规范标题切换；锁定的阶段直接写出原因；主操作始终在吸底栏。
- **意图锁定**：规范生成后，意图段默认只读；点「修改意图」才解锁，并提示可能重新生成四段规范。
- 两级确认：先确认意图，再确认规范；规范确认需校验通过并勾选，之后可「返回修改」。
- 项目、规范与工作区持久化在浏览器 `localStorage`（`dsh-RSI.projects.v2`）；旧的单规范 `dsh-RSI.evolution-spec.v1` 首次加载自动迁移成一个项目。
- 中英文、亮暗主题、窄窗口适配；无外部依赖、无构建步骤。

### 一次任务如何开始

1. **新建项目**：数据面板右上角或空状态按钮。
2. **选择工作区**：下拉选宿主已有工作区，或输入目录路径新建；这是解析意图的前置条件。
3. **输入想法**：一句自然语言描述。
4. **解析意图**：本地确定性解析器生成一段「我的理解」，并列出解析线索（目标区域、成功信号）。这一步不调用模型。
5. **校对并确认**：可以直接修改这段理解；确认后才会拆成四段规范。
6. **生成四段规范**：目标、修改空间、评估标准、执行约束，一次只展开一段，可逐项修改。
7. **确认规范**：规范页底栏校验并勾选后冻结；不会启动执行。

想法、意图、规范三段可以点击切换：想法随时可回；意图在解析后可回；规范在意图确认后可回。未满足条件的段落会禁用并提示缺什么。修改想法会让下游过期；修改意图会重新生成四段规范（默认只读，需先点「修改意图」）。

随时可以点击想法段回到输入：

- 不修改：直接返回上一步；
- 修改了：需要重新解析意图，或恢复到上次解析的想法。

自动解析只是起点；确认后的规范才交给 Phase 2 的自进化引擎。

## 安装

在 DSH 的 **插件** 页面选择 **添加插件 → 安装第三方插件**，任选一种来源：

```text
# 从 GitHub 安装
https://github.com/Nick-Hogo/dsh-rsi.git

# 从本地目录安装：填本仓库的绝对路径（在仓库根目录执行 pwd 获取）
```

安装后启用插件；新 bundle 可能需要重启 DSH。之后修改 `client/client.js` 只需刷新页面。

**关于「需要 http 或 https」**：这个提示来自对话框里的 **安装源** 字段，不是包名/路径字段。本地路径应填在 **包名或地址**，安装源保持 **默认安装源**；只有自定义 npm registry 才必须填写 `http(s)://` 地址。

如果确实需要用 URL 安装，可以把本目录打包成 `.tgz`，用任意静态 HTTP 服务托管，再把 tarball 地址填进 **包名或地址**：

```bash
npm pack --pack-destination /tmp/dsh-RSI-dist
python3 -m http.server 18765 --bind 127.0.0.1 --directory /tmp/dsh-RSI-dist
# 地址形如 http://127.0.0.1:18765/dsh-RSI-0.7.0.tgz
```

> 包名为 `dsh-RSI`。npm 新包名规范不允许大写字母；本地链接安装通常可用，若安装器拒绝，把 `package.json` 的 `name` 与 `client/client.js` 的模块 id 改为 `dsh-rsi` 即可，目录、标题和文档保持不变。

## 开发

```bash
cd dsh-RSI
npm run check
```

`check` 会做：

- `host/index.js`、`client/client.js` 语法检查；
- 包清单 / patch / locale / icon 校验；
- 客户端模块注册与 `apply()` 注册校验；
- 项目存储、旧规范迁移、规范校验、状态派生、localStorage 读写的冒烟测试。

## 边界

本阶段不实现：RSI 引擎、候选生成/评估/选择/改写、LLM 调用、工作区读写、Host 服务与 IPC。工作区绑定只是记录目标路径，引擎尚未使用它。

引擎接入后，`EvolutionSpec` 由 Host 持久化，面板通过 `EngineSnapshot` 展示真实的步骤与轮次。
